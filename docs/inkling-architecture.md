## 2. Reasoning

- **Mechanism.** The model reasons by default and emits a `<|content_thinking|>` block before the answer (shown as `reasoning_content` or an Anthropic `thinking` block). VERIFIED: chat template and parser format https://docs.vllm.ai/en/latest/api/vllm/parser/inkling ; Anthropic route https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/anthropic/index.md
- **Effort is a number, injected as a system message.** The template inserts `<|message_system|><|content_text|>Thinking effort level: 0.9<|end_message|>` before the first non-system message; default 0.9 if omitted. TML trained it by varying the system message and a per-token cost in RL. VERIFIED: https://huggingface.co/thinkingmachines/Inkling-Small/raw/main/chat_template.jinja ; https://thinkingmachines.ai/news/introducing-inkling/ ("We specified the model's effort level on different samples by changing the system message and adjusting the per-token cost") ; https://tinker-docs.thinkingmachines.ai/cookbook/inkling/thinking-effort/
- **Levels (scalar):** none 0.0, minimal 0.1, low 0.2, medium 0.7, high 0.9 (default), xhigh 0.99; any float in [0.0, 0.99] accepted. "max" = 0.99 in the HF template, SGLang, Unsloth and Tinker's Anthropic route ("max behaves the same as xhigh"). VERIFIED: https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/openai/index.md ; https://docs.sglang.io/cookbook/autoregressive/ThinkingMachines/Inkling-Small ; https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/anthropic/index.md
  - **Conflict:** the shipped `chat_template.jinja` has `effort_map = {none, minimal, low, medium, high, max}` — **no `xhigh` key**, so self-hosted vLLM/transformers reject `"xhigh"`; the NVIDIA Dynamo recipe states exactly this ("`xhigh` from the launch blog is not in its map and is rejected"). Tinker docs, the HF blog and SGLang list `xhigh`. https://docs.nvidia.com/dynamo/dev/recipes/inkling.md
  - **OpenRouter** advertises `supported_efforts: max, high, medium, low, minimal, none`, default `high`; no `xhigh`. https://openrouter.ai/api/v1/models (entry `thinkingmachines/inkling-small`).
  - **DeepInfra** generic chat-spec enum accepts none/minimal/low/medium/high/xhigh/max (not model-specific); its reasoning guide lists only none/low/medium/high. https://docs.deepinfra.com/api-reference/chat-completions/openai-chat-completions.md ; https://docs.deepinfra.com/chat/reasoning
- **Effort is a soft conditioning, not a limit.** `effort=0` "does not enforce a hard no-reasoning constraint"; effort and `max_tokens` are independent ("Higher effort may require a larger generation budget to avoid truncation"); temperature still matters. VERIFIED: https://tinker-docs.thinkingmachines.ai/cookbook/inkling/thinking-effort/
- **Thinking budget control:** none. Anthropic `thinking.budget_tokens` is "accepted for wire compatibility but is not used"; `thinking: {type: disabled}` forces reasoning off; effort goes via `output_config.effort`. VERIFIED: https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/anthropic/index.md . Reasoning tokens consume `max_tokens`; low `max_tokens` can return empty `content` with `finish_reason: "length"` (Dynamo recipe suggests ≥1500). VERIFIED: https://docs.nvidia.com/dynamo/dev/recipes/inkling.md
- **Pass-back between turns:** NOT FOUND as a stated requirement. What the template does: for every assistant message that carries `reasoning_content`, it renders `<|message_model|><|content_thinking|>…<|end_message|>` before the answer; nothing is stripped by position. The Cookbook renderer states "TMLv0 frames each message independently, so nothing is stripped or re-headered by position. Shorter prompts stay token-prefixes of longer ones." Unsloth says the model "does interleaved thinking and tool calling". Reasoning is therefore optional to pass back, and, if passed, is rendered. https://huggingface.co/thinkingmachines/Inkling-Small/raw/main/chat_template.jinja ; https://raw.githubusercontent.com/thinking-machines-lab/tinker-cookbook/main/tinker_cookbook/renderers/tml_v0.py ; https://unsloth.ai/docs/models/inkling. Whether quality improves when it is passed back: NOT FOUND.
- Which request field carries prior reasoning back at OpenRouter/DeepInfra (`reasoning`, `reasoning_content`, `reasoning_details`): NOT FOUND. The HF template reads `message.reasoning_content`.
- Style: RL made chain-of-thought "concise, telegraphic" (article/connective dropping). Inkling-Small averaged ~24K output tokens per AA Intelligence Index task (parent ~25K). VERIFIED: https://thinkingmachines.ai/news/introducing-inkling/ ; AA article.

## 3. Tool use

- **Native wire format (VERIFIED from the template):**
  - Declarations: `<|message_system|>tool_declare<|content_xml|>[{"description":…,"name":…,"parameters":{…},"type":"function"},…]<|end_message|>` — JSON compact, `sort_keys=true`, emitted **before any other message, including the system prompt**.
  - Call: `<|message_model|>NAME<|content_invoke_tool_json|>{"name":"NAME","args":{…}}<|end_message|>`; one message per call; the assistant turn closes with `<|content_model_end_sampling|>`.
  - Result: `<|message_tool|>NAME<|content_text|>CONTENT<|end_message|>` (tool name taken from `message.name`, else looked up via `tool_call_id`); only **string** tool content is rendered (list-typed tool content is dropped by the HF template).
  - Template raises if a prior call's `arguments` is a JSON *string* ("must be a parsed object") or not an object; serving layers parse before rendering.
  - A `<|content_tool_error|>` token and `ToolError` type exist; SGLang also handles a raw `<|content_invoke_tool_text|>` header-less invocation fallback.
  - Sources: https://huggingface.co/thinkingmachines/Inkling-Small/raw/main/chat_template.jinja ; https://docs.vllm.ai/en/latest/api/vllm/parser/inkling ; https://github.com/sgl-project/sglang/pull/32861 ; https://pypi.org/project/tml-renderers/
- **Parallel tool calls:** the format *can* express several calls in one turn (repeated blocks; the Cookbook says "A model turn can span several messages (thinking, text, tool calls)"; vLLM parser: "Blocks … may repeat in any order"; SGLang: "all-or-nothing batch semantics"). No TML statement that the model was trained or evaluated for parallel calls. OpenRouter lists **no** `parallel_tool_calls` parameter for the model. So: representable, not documented as a supported/trained behaviour; consistent with the observed near-zero parallel rate. https://github.com/thinking-machines-lab/tinker-cookbook ; https://docs.vllm.ai/en/latest/api/vllm/parser/inkling ; https://openrouter.ai/api/v1/models/thinkingmachines/inkling-small/endpoints. Why the model rarely emits them: NOT FOUND (INFERRED: one-call-per-message framing).
- **Known tool-call failure modes (all third-party; none acknowledged by TML):**
  1. Model sometimes samples an HTML entity (`&quot;`) where a JSON quote belongs, mostly right after a URL; hand-rolled parser fails to close the string and falls back to emitting the raw `<|content_invoke_tool_json|>{…}<|end_message|>` as *content*. Single community source; claims temperature does not remove it. https://raw.githubusercontent.com/iruleee/inkling-small-nvfp4-dgx-spark/main/mods/inkling-tool-unescape-pr329/README.md
  2. Streaming: a turn that opens directly with a tool call (no thinking block) leaks the whole tool block into `content` with `tool_calls == []`. vLLM #50512 (closed; fix referenced as #50528). https://github.com/vllm-project/vllm/issues/50512
  3. `<|end_message|>` / `<|content_model_end_sampling|>` leaking into content: with `reasoning_effort` none/minimal (vLLM #49865, open) and on the synthesis turn after a tool result when tools are present (vLLM PR #51391). https://github.com/vllm-project/vllm/issues/49865 ; https://github.com/vllm-project/vllm/pull/51391
  4. SGLang fixed: text after a tool call dropped; malformed/partial payload silently dropped; header-less `<|content_invoke_tool_text|>` never reached execution. https://github.com/sgl-project/sglang/pull/32861
  5. Which parser DeepInfra/TML run, and whether they carry these bugs: NOT FOUND. **INFERRED**: the harness-observed "~3% of Read calls with `pages` come out as text" fits failure mode 1/2 (parser fallback to raw text) but I found no source naming `pages` specifically.
- **Structured output:** NOT FOUND for the model by TML. OpenRouter lists no `response_format`/`structured_outputs` for either Inkling-Small endpoint; DeepInfra's page badge shows "JSON" and its generic API spec supports `json_object`, `json_schema`, `regex`; vLLM recipe notes a 4×H100 W4A16 deployment returned HTTP 500 on JSON-schema output (vLLM #51693). Status: conflicting, provider-dependent. https://openrouter.ai/api/v1/models/thinkingmachines/inkling-small/endpoints ; https://deepinfra.com/thinkingmachines/Inkling-Small/api ; https://recipes.vllm.ai/thinkingmachines/Inkling-Small
- **tool_choice:** DeepInfra endpoint `none/auto/required` = true, forcing a *named function* = **false**; TML's own free endpoint supports none of tool_choice (all false). VERIFIED: endpoints APIs above. Tinker Anthropic route supports auto/any/named/none. https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/anthropic/index.md
- **Recommended tool-schema style:** NOT FOUND. TML only says it "randomized the tool set and schema during training to reduce sensitivity to any particular one". https://thinkingmachines.ai/news/introducing-inkling/

## 4. Training

- **Pretraining:** Inkling 45T tokens of text/image/audio/video (parent post). Inkling-Small: different data mix and ML recipe, token count NOT FOUND. https://thinkingmachines.ai/news/introducing-inkling/ ; https://thinkingmachines.ai/news/inkling-small/

VERIFIED: https://thinkingmachines.ai/news/introducing-inkling/

## 6. Modalities

- Input text, image, audio; output text only. VERIFIED: model card; OpenRouter `text+image+audio->text`.
- Images: native, encoder-free; 40×40 patches through a 4-layer hMLP. Model card: "any pixel-based image", each dimension 40–4096 px; small-edge images upscaled (long edge → min(2048, 2× original)). Tinker cookbook accepts **PNG and JPEG** only, via path, `file://` or base64 data URI; remote URLs are not fetched by the client (servers such as vLLM/SGLang do fetch HTTP(S) URLs). OpenAI-style `image_url` and Anthropic `base64`/`url` image sources work. https://thinkingmachines.ai/model-card/inkling-small/ ; https://tinker-docs.thinkingmachines.ai/cookbook/inkling/images/index.md ; https://recipes.vllm.ai/thinkingmachines/Inkling-Small
- Audio: native, dMel spectrograms (80 mel bins, 100 ms chunks); WAV 16 kHz recommended; WAV/MP3/FLAC accepted by cookbook; `input_audio` or `audio_url` parts. **Not** supported on Tinker's Anthropic route. Length guidance conflicts: model card "ideally under 2 mins"; Dynamo recipe says "under 20 minutes". https://tinker-docs.thinkingmachines.ai/cookbook/inkling/audio/index.md ; https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/anthropic/index.md ; https://docs.nvidia.com/dynamo/dev/recipes/inkling.md
- Video: **not supported out of the box** (trained on video data, temporal patch dim exists, but "we haven't evaluated out-of-the-box video performance"). https://github.com/huggingface/blog/blob/main/thinkingmachines-inkling.md
- Visual tool use: model trained to use Python for crop/zoom/inspection of images. https://thinkingmachines.ai/news/inkling-small/
- Provider caveat: Dynamo's vLLM profile silently drops media if `--enable-multimodal` is forced without support (returns an answer invented from text) — serving-stack specific. https://docs.nvidia.com/dynamo/dev/recipes/inkling.md

## 7. Serving

- **OpenRouter listing (only one paid endpoint at time of research): DeepInfra, tag `deepinfra/fp8`**, context 524,288, max completion 262,144, $0.45 in / $1.20 out / $0.10 cache-read per M, `supports_implicit_caching: true`, uptime 100%. https://openrouter.ai/api/v1/models/thinkingmachines/inkling-small/endpoints
- **Free variant:** `thinkingmachines/inkling-small:free`, provider "Thinking Machines", `nvfp4`, context 1,048,576, `supports_implicit_caching: false`, no tool_choice, no top_k/min_p/penalties other than frequency/presence. A search snippet of a TML engineer's post says the free tier exists "to help us understand [Inkling's] real-world behavior … only with agentic harnesses" — i.e. TML collects traffic; treat as non-private. https://openrouter.ai/api/v1/models/thinkingmachines/inkling-small:free/endpoints ; https://x.com/ekzhang1/status/2090891509637755078 (snippet only; the fetched mirror showed the shorter "hosting Inkling and Inkling-Small … for free in your favorite agent harness")
- DeepInfra page: "Zero retention", fp8, 524,288 context, badges JSON / Function / Multimodal. https://deepinfra.com/thinkingmachines/Inkling-Small/api
- **Caching.** DeepInfra: automatic prefix KV reuse, matched from the first token ("even a single character difference will invalidate the cache"), per-model and per-account, entries "expire after a period of inactivity" (length not stated), optional `prompt_cache_key` (session-scoped) to improve hit rate.   - OpenRouter: sticky routing keeps a conversation on the same provider for 10 minutes after the last request; key = hash of first system + first non-system message, or `session_id` body field / `x-session-id` header / `prompt_cache_key`. ## 8. Other things a harness author should know

- Documented limitations (TML): hallucination, "occasional failures to follow instructions precisely", "degraded performance in long multi-turn conversations". https://thinkingmachines.ai/model-card/inkling-small/
- Factuality is the trade-off for coding/reasoning gains: SimpleQA Verified 20.6% vs parent 43.9%; AA-Omniscience −9; τ³-Banking 15.5% vs 23.7%. Do not rely on recalled API/library facts; make the agent read files/docs. https://thinkingmachines.ai/news/inkling-small/
- Terminal-Bench numbers depend on harness (64.7 internal / 61.2 bash-only / 55 on AA's independent run). https://huggingface.co/thinkingmachines/Inkling-Small/discussions/6 ; AA article
- Vision/audio queries: model first transcribes/OCRs then reasons; effort helps reasoning, not hearing (HF vibe-evals, parent model). https://github.com/huggingface/blog/blob/main/thinkingmachines-inkling.md
- Do not put your own "Thinking effort level" text into the conversation; the renderer injects it and errors on duplicates (tml-renderers). https://pypi.org/project/tml-renderers/
- "Inkling generates complete assistant messages; it does not continue from a partially written assistant message" — assistant prefill is not supported by the TML renderer. https://tinker-docs.thinkingmachines.ai/cookbook/inkling/tml-renderers/
- Tinker's own endpoints are beta, "intended for low-traffic testing". https://tinker-docs.thinkingmachines.ai/tinker/compatible-apis/anthropic/index.md ; https://developers.cloudflare.com/ai/models/thinkingmachines/inkling
